## Devices

What is wired to the board beside the panel and the touch. `hw_init()` starts each one and
`hw_poll()` reads it on its own interval (`hardware.cpp`); the screens and your own code read
the last reading, so a slow or missing part never holds the screen up. `<name>_ok()` is
whether the part answered when the board started.

| I2C (GPIO 47 / 48) (I2C) | SDA `47`, SCL `48` | 400 kHz |

## Build

### Arduino IDE

1. Unzip the project and keep the `MyUI` folder whole: `MyUI.ino` has to stay inside it, with `src/` and the other files beside it.
2. Install the libraries listed in **LIBRARIES.md** from the Library Manager, at the versions it gives: **lvgl 9.4.0**, **GFX Library for Arduino 1.6.9**, **SensorLib 0.5.1**. The Library Manager offers the newest - pick the version from the list beside **Install** first.
3. Open `MyUI.ino`, select **ESP32-S3**, and upload.

The IDE shows the files beside the `.ino` as tabs. The screens, fonts and images are in `src/ui/`, which it compiles with the sketch but does not open - `src` is the one
subfolder the Arduino IDE builds, so do not rename or move it.

`lv_conf.h` stays where it is: the ESP32 core (3.0 or newer) reads it from the sketch folder,
so each project keeps its own and there is nothing to copy into `libraries/`.

**ESP32 core:** in the Boards Manager, install *esp32 by Espressif Systems* **3.1.0 or newer**. This export is built against 3.3.
- GFX Library for Arduino 1.6.9 needs 3.1.0. On an older core the build stops at `'esp_lcd_i80_bus_config_t' has no non-static data member named 'dma_burst_size'`.

Before uploading, set these in **Tools** to match the N16R8 module:

| Menu | Choose |
|---|---|
| Flash Size | 16MB (128Mb) |
| PSRAM | OPI PSRAM |
| Partition Scheme | Custom |
| USB CDC On Boot | Enabled |

The flash is divided by `partitions.csv`, which the IDE uses because it sits beside
the sketch - whatever Partition Scheme says. *Custom* only tells the size check to
allow it, and needs ESP32 core 3.0 or newer. Keep the sketch under the 12 MB app partition.

Get the PSRAM setting right: LVGL's memory pool is allocated from PSRAM, so without it the sketch stops at `lv_init()`.

### PlatformIO

First time with VS Code and PlatformIO? https://lcdwizard.com/docs/build-platformio goes through every click, from installing VS Code to the first upload.

```bash
pio run -t upload
```

### Image assets

The images live in `data/` and are flashed **separately** from the sketch:

```bash
pio run -t uploadfs
```

That is PlatformIO. Skip the upload and every image draws as an empty box.

**Arduino IDE:**

**The Arduino IDE 2 SPIFFS uploader cannot be used with this project.** It takes the filesystem's
position from Tools > Partition Scheme and knows only the core's stock schemes, and none of them
is this N16R8 layout. Two ways round it:

- **Switch to LittleFS** in LCD Wizard (Assets > Filesystem) and export again. Its uploader,
  arduino-littlefs-upload, reads `partitions.csv` from the sketch folder and works with any layout.
- Or build and write the image yourself, with the two tools the ESP32 core installed (under
  `Arduino15/packages/esp32/tools/`, in `mkspiffs` and `esptool_py`). From the sketch folder:

```bash
mkspiffs -c data -p 256 -b 4096 -s 0x3E0000 spiffs.bin
esptool --chip esp32s3 --port <PORT> --baud 921600 write_flash -z 0xC10000 spiffs.bin
```

See `data/README.md` for the size budget.

## Editing the UI

Every file of this export is written fresh with every export, `src/ui/ui_events.c` included: it holds the stubs for your Call function events, and a new export unzipped over
this folder replaces a copy you have filled in. Keep your own copy and copy it back, or put your code in a
file of your own beside the sketch, which no export contains, and tick "Do not export to code" on the events
whose functions are there.

## Your own code: setup and loop hooks

*My own code: setup and loop hooks* is on (File > Project settings > Your own code). The sketch calls
`user_pre_ui_setup()` once, after the board is powered (its power chip, expanders and start-up lines) and
before the panel, the touch panel and LVGL start; `user_setup()` once, after the panel, the touch panel, the
devices, the screens and the variables are up; and `user_loop()` on every pass of `loop()`, before LVGL draws.
`lw_user.cpp` has empty ones, so the sketch builds without yours. Write yours in a `.cpp` file of your own in
this folder, for example `my_code.cpp`:

```cpp
#include <Arduino.h>
#include "src/ui/ui.h"   // every widget, as ui_<Name>

void user_pre_ui_setup(void) { }   // before the screen starts: keep it short
void user_setup(void) { }
void user_loop(void) { }   // every pass: never wait in it
```

- **`user_pre_ui_setup()` is for hardware that must be set up before the screen starts.** The screen stays dark
  while it runs, so never wait for Wi-Fi or anything slow there: show "Connecting..." on a screen and wait with
  an automation instead.

- **No export contains your file**, so unzipping a new export over this folder leaves it as it is.
- **A library of your own** is included at the top of your file. Install it with the Library Manager of the Arduino IDE,
  or add it to `lib_deps` in `platformio.ini` - which every export writes fresh, so add it again after each one.
- **Use the buses the sketch has started** (`Wire`, `Wire1`, `SPI`) and do not begin them again.
- **Set a label** with `snprintf()` and `lv_label_set_text()`, and only when the text has changed;
  `lv_label_set_text_fmt()` prints no `%f` with this `lv_conf.h`.

## Drawing on a Canvas

Each Canvas is an `lv_canvas` declared in `ui.h`. Its pixels are a buffer of its own, given to it when
its screen is built and freed when the screen is deleted (`lw_canvas.c`), from PSRAM, or internal RAM if there is no PSRAM to be had.

| Canvas | Screen | Pixels | Buffer |
|---|---|---|---|
| `ui_CanvasCandleDayChart` | Bitcoin_Screen_1 | 216 x 136 | 57.4 KB |

Draw from your own code once its screen is built - a Screen loaded event that calls a function of yours is the
usual place - and only while it has a buffer: `ui_canvas_buffer(ui_CanvasCandleDayChart)` is NULL when there was not the
memory for one.

```c
#include "lw_canvas.h"

if (ui_canvas_buffer(ui_CanvasCandleDayChart)) {
    lv_canvas_set_px(ui_CanvasCandleDayChart, 10, 10, lv_color_hex(0xFF0000), LV_OPA_COVER);

    /* Anything LVGL can draw, through a layer (LVGL 9) */
    lv_layer_t layer;
    lv_canvas_init_layer(ui_CanvasCandleDayChart, &layer);
    lv_draw_rect_dsc_t rect;
    lv_draw_rect_dsc_init(&rect);
    rect.bg_color = lv_color_hex(0x2196F3);
    lv_area_t a = { 20, 20, 60, 50 };
    lv_draw_rect(&layer, &rect, &a);
    lv_draw_line_dsc_t line;
    lv_draw_line_dsc_init(&line);
    line.color = lv_color_hex(0x000000);
    line.width = 2;
    line.p1.x = 0; line.p1.y = 0; line.p2.x = 100; line.p2.y = 60;
    lv_draw_line(&layer, &line);
    lv_canvas_finish_layer(ui_CanvasCandleDayChart, &layer);
}
```

The Clear canvas action, and `ui_canvas_clear(canvas, colour, opacity)` from your own code, wipe it to one colour.
A widget variable of a screen that has been deleted is not cleared, so ask `lv_obj_is_valid()` before drawing on
a canvas from a timer of your own that may outlive its screen.

## Troubleshooting

| Symptom | Usual cause |
|---|---|
| Dozens of errors when compiling | Almost always a library or ESP32 board package version. Install the versions in **Build** above; the first message of the build names a wrong lvgl or board package and what it needs. |
| Black screen | This panel has no backlight pin - it is its own light. Check its reset line, any line `setup()` drives before the panel to switch its supply, and the start-up sequence on the Display tab. |
| Too dim, or does not dim | Brightness is the panel's own, a command to its controller: it starts at the Display tab's **Default %** on every boot, and a Set backlight event on a slider or buttons changes it. |
| Colours inverted | Toggle **Invert** in the Display tab (`cfg.invert`). |
| Red and blue swapped | Switch the colour order between RGB and BGR. |
| Mirrored or rotated image | Change **Rotation** - touch follows it. |
| Touch offset or mirrored | Toggle Swap X/Y, Invert X, Invert Y in the Touch tab. |
| Touch stops responding | Serial shows `touch: controller stopped answering - resetting it` when the firmware resets it. Repeated, check its RESET wiring and power. At boot, `nothing answering` means SDA, SCL, the address or RESET. |
| Random pixels or tearing | Lower the SPI clock, or shorten your wires. |
| Reboot loop on start | The draw buffer is too big - lower `DRAW_BUF_LINES`. |
| A file from `data/` is not on the board (pictures are empty boxes, a file reads as missing) | `data/` is not part of the sketch upload: it goes on with an upload of its own - see **Image assets** above. |
| SD card: size reads 0 | The card is looked for once, when the board starts: put it in before powering up. FAT32; if it mounts only sometimes, lower the device's clock. |

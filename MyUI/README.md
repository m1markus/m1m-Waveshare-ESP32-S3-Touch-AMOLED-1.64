## Devices

What is wired to the board beside the panel and the touch. `hw_init()` starts each one and
`hw_poll()` reads it on its own interval (`hardware.cpp`); the screens and your own code read
the last reading, so a slow or missing part never holds the screen up. `<name>_ok()` is
whether the part answered when the board started.

| I2C (GPIO 47 / 48) (I2C) | SDA `47`, SCL `48` | 400 kHz |

## Build

### Arduino IDE

1. Unzip the project and keep the `MyUI` folder whole: `MyUI.ino` has to stay inside it, with `src/` and the other files beside it.
2. Install the libraries listed in **LIBRARIES.md** from the Library Manager, at the versions it gives.
3. Open `MyUI.ino`, select **ESP32-S3**, and upload.

The IDE shows the files beside the `.ino` as tabs. The screens, fonts and images are in `src/ui/`, which it compiles with the sketch but does not open - `src` is the one
subfolder the Arduino IDE builds, so do not rename or move it.

`lv_conf.h` stays where it is: the ESP32 core (3.0 or newer) reads it from the sketch folder,
so each project keeps its own and there is nothing to copy into `libraries/`.

**ESP32 core:** in the Boards Manager, install *esp32 by Espressif Systems* **3.1.0 or newer**. This export is built against 3.3.
- GFX Library for Arduino 1.6.9 needs 3.1.0. On an older core the build stops at `'esp_lcd_i80_bus_config_t' has no non-static data member named 'dma_burst_size'`.

Before uploading, set these in **Tools** to match the N16R8 module:

| Menu | Choose |
|---|---|
| Flash Size | 16MB (128Mb) |
| PSRAM | OPI PSRAM |
| Partition Scheme | Custom |
| USB CDC On Boot | Enabled |

The flash is divided by `partitions.csv`, which the IDE uses because it sits beside
the sketch - whatever Partition Scheme says. *Custom* only tells the size check to
allow it, and needs ESP32 core 3.0 or newer. Keep the sketch under the 12 MB app partition.

Get the PSRAM setting right: LVGL's memory pool is allocated from PSRAM, so without it the sketch stops at `lv_init()`.

pio run -t upload

## Editing the UI

Every file of this export is written fresh with every export, `src/ui/ui_events.c` included: it holds the stubs for your Call function events, and a new export unzipped over
this folder replaces a copy you have filled in. Keep your own copy and copy it back, or put your code in a
file of your own beside the sketch, which no export contains, and tick "Do not export to code" on the events
whose functions are there.

## Troubleshooting

| Symptom | Usual cause |
|---|---|
| Black screen | This panel has no backlight pin - it is its own light. Check its reset line, any line `setup()` drives before the panel to switch its supply, and the start-up sequence on the Display tab. |
| Too dim, or does not dim | Brightness is the panel's own, a command to its controller: it starts at the Display tab's **Default %** on every boot, and a Set backlight event on a slider or buttons changes it. |
| Colours inverted | Toggle **Invert** in the Display tab (`cfg.invert`). |
| Red and blue swapped | Switch the colour order between RGB and BGR. |
| Mirrored or rotated image | Change **Rotation** - touch follows it. |
| Touch offset or mirrored | Toggle Swap X/Y, Invert X, Invert Y in the Touch tab. |
| Touch stops responding | Serial shows `touch: controller stopped answering - resetting it` when the firmware resets it. Repeated, check its RESET wiring and power. At boot, `nothing answering` means SDA, SCL, the address or RESET. |
| Random pixels or tearing | Lower the SPI clock, or shorten your wires. |
| Reboot loop on start | The draw buffer is too big - lower `DRAW_BUF_LINES`. |
| SD card: size reads 0 | The card is looked for once, when the board starts: put it in before powering up. FAT32; if it mounts only sometimes, lower the device's clock. |
